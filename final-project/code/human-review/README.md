# Human review notebooks

Use the notebook for your assigned reviewer:

| Notebook | Who uses it | Answer file |
| --- | --- | --- |
| [reviewer_1.ipynb](reviewer_1.ipynb) | Reviewer 1 | `reviewer_1.csv` |
| [reviewer_2.ipynb](reviewer_2.ipynb) | Reviewer 2 | `reviewer_2.csv` |
| [review_coordinator.ipynb](review_coordinator.ipynb) | Coordinator | Packet preparation, completion counts, combined results, and interpretation |

The separate notebooks have their reviewer IDs preconfigured. Leave those IDs unchanged. Each notebook contains the same rubric and article-reading, rating, saving, and progress cells, but neither contains the coordinator's combined-score or interpretation cells.

The coordinator notebook contains no individual rating-entry cells and never edits reviewer answers. The analysis notebooks remain in `../modern-methods/notebooks/`.

## Start or resume your review

1. Start Jupyter with `uv run jupyter lab` from the repository environment.
2. Open your assigned notebook. Both people review the same frozen article sample independently.
3. Leave `PACKET_FOLDER = None` to follow the selected modern run. Set an absolute path only if the coordinator gave you a different packet folder.
4. Run the setup and configuration cells. These load your existing answer CSV; they do not reset it or create a replacement packet.
5. Read the rubric and display the next unfinished item. Fill in its rating, flags, notes, and displayed item number; set `SAVE_RATING = True` to save deliberately.
6. Repeat the display and entry cells. Use the progress cell to check unfinished items. To resume later, reopen your notebook and reload the same packet folder.
7. Send your own CSV to the coordinator when complete. Do not inspect the other reviewer's answers or replace independent scores with consensus scores.

Before entering real ratings, save a personal copy as `reviewer_1_workbook.ipynb` or `reviewer_2_workbook.ipynb` inside the packet folder. These working copies are ignored by Git. Clearing outputs alone does not remove ratings typed into source cells; keep the checked-in notebooks as blank templates.

## Packet location and prerequisites

Splitting the notebooks does not move any packets or saved answers. The default location remains:

```text
final-project/code/modern-methods/Results/comparison/<selected-run>/human_review/
```

Each reviewer needs `review_packet.csv`, `review_freeze.json`, `review_status.json`, and their own CSV. They do not need the other person's answer file. The packet and labels must already be frozen through [the comparison notebook](../comparison/pipeline_comparison.ipynb); missing inputs produce a pending message. No model is selected and no ratings are generated by these notebooks.

The coordinator collects both completed CSVs and runs the summary section of `review_coordinator.ipynb`, or reruns [the comparison notebook](../comparison/pipeline_comparison.ipynb). Full-text packets and individual answers remain local/ignored by Git.

## Validation

From the repository root:

```sh
uv run python final-project/code/modern-methods/verify_notebooks.py
uv run python final-project/code/modern-methods/verify_notebooks.py --execute reviewer_1 reviewer_2
uv run python final-project/code/modern-methods/verify_notebooks.py --execute coordinator
```

The first command validates the three analysis notebooks, the coordinator notebook, and both reviewer notebooks. The second executes only the two individual notebooks; with their default blank entry cells it saves no answers. The coordinator defaults check available files and completion counts without producing a combined summary. `--execute 04` remains a compatibility alias for `--execute coordinator`. Do not use automated execution on a personal workbook containing edited save cells.
